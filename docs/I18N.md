# Internationalisation & Bengali-First Copy Rules

The product ships Bengali-first with English available. Copy, formatting, and
font handling are part of the design system, not an afterthought.

---

## 1. Locales

| Locale | Code | Status |
| --- | --- | --- |
| Bengali | `bn-BD` | **default** |
| English | `en-US` | full |

- Source strings live in `src/i18n/locales/en-US.json`; Bengali is the
  translated target, reviewed by a human.
- Never hardcode user-visible strings in a component.
- `<html lang="bn-BD">` is set at boot from the resolved locale.

---

## 2. Font

All Bengali text renders in **Anek Bangla Variable**, self-hosted
(`assets/fonts/anek-bangla/`). No CDN.

| Rule | Value |
| --- | --- |
| Body line-height | ≥ 1.6 (`--leading-bangla: 1.75`) |
| Heading line-height | ≥ 1.4 — never `leading-none` |
| Letter-spacing | 0 for Bengali; `-0.02em` only for Latin display headings |
| Mixed script | the same family covers both; do not switch fonts mid-sentence |

Bengali text is taller than Latin. Reserve vertical space in cards, buttons,
and badges so a Bengali label does not clip.

---

## 3. Numbers, Currency, Dates

Always use `Intl` with the active locale. Never hand-format.

| Value | bn-BD | en-US |
| --- | --- | --- |
| 125000 | `১,২৫,০০০` (lakh grouping) | `125,000` |
| USD 19 | `$১৯.০০` or `US$ 19.00` per locale data | `$19.00` |
| BDT 1500 | `৳১,৫০০.০০` | `BDT 1,500.00` |
| Date | `৮ নভেম্বর, ২০২৬` | `Nov 8, 2026` |
| Time | `২:৩০ PM` | `2:30 PM` |
| Relative | `৩ দিন আগে` | `3 days ago` |

Rules:

- Currency symbol comes from `Intl.NumberFormat`, not a hardcoded `৳`/`$`.
- `৳` is `U+09F3`, covered by the Bengali subset.
- Use `bn-BD-u-nu-latn` only if a screen must show Latin digits (e.g. an API
  key or order number).
- **Order numbers, invoice numbers, file sizes, and API keys stay Latin.**
  Translating identifiers breaks support and search.
- Never do arithmetic on a localized string. Amounts arrive as decimal strings.

## 4. Translation Keys

```
common.save
common.cancel
auth.login.title
auth.login.invalidCredentials
order.status.pending_brief        ← keys mirror the DB enum
order.action.requestRevision
vault.empty.title
errors.insufficient_funds
```

- `order.status.*` keys are generated from the canonical status list in
  `UI_SCREEN_SPECS.md` §2. Adding a status means adding a key in both locales.
- No string concatenation for sentences; use ICU placeholders:
  `"Revisions used: {used} of {limit}"`.
- Plurals use ICU plural rules, even where Bengali has one form, so English
  stays correct.

---

## 5. Copy Rules

- Buttons are verbs: **"I approve"** → "Approve delivery", not "OK".
- Destructive confirmations name the action and the consequence.
- Errors say what happened and what to do next; never expose a raw backend
  message or an error code alone.
- Empty states invite an action ("Your vault is empty · Browse catalogue").
- Avoid English loanwords where a common Bengali term exists, but keep
  established technical terms (API, PDF, ZIP, download) in Latin script.
- Do not translate product names, service titles, or user-entered content.

---

## 6. Layout Safety

- Bengali labels run ~15–25% longer than English. Buttons use `min-width`, not
  fixed width.
- Tables allocate width per column, not per header string.
- Truncation is allowed only for user content, never for a translated label.
- Test every screen at `bn-BD` before sign-off; a layout that only works in
  English is not done.

---

## 7. Locale Switching

- Stored in `ui.store` + `localStorage` key `locale`.
- Resolution order: explicit choice → browser `navigator.language` → `bn-BD`.
- Switching updates `<html lang>`, `Intl` formatters, and the font stack (no
  visual jump — same family).
- Server-side messages remain English; the client maps `error.code` to a
  localized string. Never display the raw `error.message`.
